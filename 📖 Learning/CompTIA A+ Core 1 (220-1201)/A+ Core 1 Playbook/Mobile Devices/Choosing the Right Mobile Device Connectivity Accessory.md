# <span class="rune">ᚲ</span> Choosing the Right Mobile Device Connectivity Accessory

> *The exam names a use case; you name the port or accessory.*

---

## 🎯 Problem

A scenario describes what a mobile device needs to connect to, or what accessory a user wants. Pick the right connection method or accessory.

---

## 🤔 Mental Model

| Signal in the scenario | Answer |
|---|---|
| "connect a laptop to two external monitors and a dock at once" | Docking station |
| "extend available ports on a laptop" | Port replicator |
| "tap phone to a payment terminal" | NFC |
| "share a laptop's internet connection with a phone, no cables" | Tethering/hotspot |
| "draw directly on screen" | Stylus / drawing pad |
| "use a mouse-like surface without an external mouse" | Trackpad/track point |
| "pair wireless earbuds" | Bluetooth |
| "fast-charge and transfer data on a modern Android phone" | USB-C |
| "connect to an older iPhone" | Lightning |

---

## 🧠 Why This Pattern Works

Connection methods are about the *physical or wireless link*; accessories are the *peripheral device* using that link. The exam tests both independently — a stylus needs no specific connection method named, while NFC/Bluetooth/USB-C are pure connection-method questions. Reading whether the scenario asks "how does X connect" vs. "what accessory does X need" tells you which list to search.

---

## 🚨 Common Mistakes

- Assuming all modern phones use USB-C — older/legacy Apple devices use Lightning
- Confusing NFC (tap, very short range) with Bluetooth (pair, longer range) when a scenario just says "wireless"
- Forgetting a docking station and a port replicator solve the same problem at different scales — full desktop replacement vs. just more ports

---

## 💡 Wisdom from Mímir

When a mobile scenario mentions a specific *use case* ("tap to pay," "extend a laptop's ports"), match the use case to the accessory family before worrying about the underlying wireless standard — the exam usually only needs one or the other, not both.
